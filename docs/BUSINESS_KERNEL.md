# Business kernel: contracts before calculations

本次重构将重复的底层规则集中到共享内核，保留现有 HTTP、Web UI、任务存储和工作簿导出接口。行业模块仍负责理解业务表及其计算口径；它们不能自行把未知金额变成零、按行顺序解决主数据冲突，或改变退款分摊总额。

## Execution path

```text
User request + explicitly selected sources
    → structured task scope / approved business rules
    → operation allowlist and parameter validation
    → shared execution gate
    → business kernel + domain adapter
    → business constraints and source reconciliation
    → existing workbook exporter
    → artifact acceptance + task acceptance
```

AI 可以提出计划，不能绕过这些约束，也不能执行生成的任意 Python。标准本地流程及本次回归测试不依赖外部 AI API。

## Module boundaries

| Module | Responsibility |
| --- | --- |
| `task_contract.py` | 将明确期间、实体及 Top N 绑定到实际字段；输出可序列化的 `TaskScope` |
| `operation_contracts.py`, `nl_agent.py` | 参数白名单、执行前范围校验、行业适配器调用与约束证据收集 |
| `business_kernel.py` | 严格数值、完整性求和、主数据唯一性、事件身份、货币分摊、期间并集和截止日 |
| `business_contracts.py`, `business_rules.py` | 既有指标语义、确认的粒度、状态、关联与业务政策 |
| Industry reports | 业务角色识别、行业计算和结果解释；逐步复用共享内核 |
| `task_acceptance.py` | 区分“文件能打开”和“业务要求已满足” |
| `trusted_automation.py`, `server.py` | 内核版本、授权失效、后台任务与结果复用边界 |
| `workbook_fidelity.py` | 保护原工作簿、文字类型和原生 Table 范围；拒绝破坏公式或复杂布局 |

这不是把所有行业代码重写成一个万能公式。现有业务规则和适配器仍然存在；本轮迁移解决经反例证实的公共错误，未宣称全部旧模块都已完成契约迁移。

## Invariants

1. **未知不是零。** 空事件集合可为零；有事件而金额、数量或成本缺失时，完整性求和返回未知。JSON 用 `null`，表内保留空值，并通过约束标记待核验。
2. **数字不是单位换算。** `10%` 仅在比例字段解析；不能作为单价或工资。`1箱` 不能自动成为 1 件。逗号含义不明确的数字不猜测地域格式。
3. **单据不是明细粒度。** 同单不同 SKU/行/单位不能仅按单号删除；同业务键冲突必须确认版本或明细身份。主档同键冲突不取第一条或最后一条。
4. **源现金金额守恒。** 退款按已声明的权重分摊到货币最小单位。默认最大余数法；已有明确“尾差归末行”政策仍显式采用该方法。两种方法都保证非负、零权重不收尾差、合计等于源金额。
5. **状态先语义后计算。** 取消、撤销、待审核等不能因文本里出现“完成/入库/支付”就生效。
6. **期间属于全部事实域。** 退款或结算独有月份不能被销售月份的左连接抹掉。流量期间与累计库存截止日分别处理。
7. **范围先绑定后聚合。** 已支持的明确范围必须有来源、纳入/排除行数与验收证据，不能匹配失败后回退整表。
8. **文件通过不等于任务通过。** 任一约束未满足时，任务不能因为 XLSX 序列化成功而变成完整交付。

## Scope support and limits

目前支持明确的年月、完整日期范围、截止日及可唯一绑定的实体限制。无年份月份只有在源日期年份唯一时才绑定。通用排名支持 1–30 名。多对象并集/交集、否定条件、复杂表达式或无法唯一绑定的字段需要明确规则；不执行猜测范围。

库存适配器保留期初之后截至截止日的历史流水，只把采购/销售期间汇总按起始日筛选。请求截止日晚于源数据覆盖时标记待核验，不能把较早库存冒充月末库存。

多事实经营诊断与订单退款的期间限制不能在关联前截断原订单和退款。因此这类显式期间任务目前需要进一步确认发生月/订单归属月及追溯边界；尚未接入该范围契约时明确拒绝自动截断。完整行业报告保留原有双时间视角。

行业报表尚未绑定 Top N 的路径也明确拒绝此约束；不能仅因为内核能识别“前8名”就声称任意行业已支持它。适配器缺少实体字段时不会将未筛选事实混入结果。

## Migration covered in this change

- 客户订单：空异常表、已发生退款状态、退款身份冲突、金额分摊和源金额勾稽。超出原订单实付的源退款不擅自截断，保留现金事实并要求核对补偿、运费或跨期口径；缺少退款状态的旧数据为暂定事实并披露核验。
- 库存：明细身份、状态、截止日、未知期初/数量/单位、补货建议完整性及期间流量。
- 人员：缺失考勤不等同缺勤，金额不解析百分号；无效调整不能变成零薪资调整，主档冲突拒绝按行顺序解决。评分/工作日默认值仍是管理假设，不是法定薪资结算依据。
- 餐饮：缺失食材成本不生成确定贡献，退款单去重和守恒、订单门店/月份身份检查。
- 电商：退款和主档冲突、跨月退款/结算月份并集、成本证据完整性与空风险清单。
- 保真导出：文字不变公式，Table/筛选范围随授权替换同步；源文件同路径覆盖、含公式或复杂布局的矩形覆盖被拒绝，可追加结果表。
- 任务存储与定时器：每次事务显式提交/回滚并关闭 SQLite 连接，避免依赖垃圾回收释放 Windows 文件句柄；后台任务引擎原有关闭机制保留。
- 启动不自动删除过期任务；保留期限表示过期阈值。显式清理会在删除前跳过当前、已加载和有后台作业的任务。

采购单位换算仍必须有可信单位系数；行业局部的估算贡献不升级为会计净利润。其他旧适配器的默认政策仍需分别审计，不从这些修复外推“任意 Excel 都正确”。

## Tests and independent controls

`tests/test_kernel_regressions.py` 使用小规模反例覆盖此前错误，不依赖客户标准答案。`tests/test_business_kernel.py` 对两种舍入政策执行随机守恒检查。`tests/test_kernel_delivery.py` 通过实际 localhost HTTP 后台任务下载并回读 XLSX，核对范围、原始输入、图表和版本复用，同时覆盖库存期间与累计余额。

既有客户订单 Golden Test 的退款误差曾为 2 分；断言改为独立读取源退款和有效订单金额，用 Decimal 勾稽，不以旧错误合计为标准，也不放宽误差容忍度。

本地运行：

```powershell
python -m pytest -q tests/test_business_kernel.py tests/test_kernel_regressions.py tests/test_kernel_delivery.py
python -m pytest -q
```

## Upgrade and restart

计算内核版本纳入自动授权和任务缓存身份。代码变更后旧授权需要重新核对，新请求不能直接复用旧内核的结果。排队时内核变更会阻止旧目标执行。

执行中断的任务不能通过升级内核或换缓存键自动重跑。先核对已有输出，再以独立任务重做。这里只授权本地数据处理；采购、付款、发布和人员处置没有获得额外执行权限。

服务启动后 `/health` 的 `business_kernel: contracts-v1` 可确认新内核已加载。此字段表示架构代际，任务实际缓存仍使用模块内容指纹。源码安装和冻结字节码均可计算指纹；指纹不可验证时拒绝自动授权。
