# 程序化执行底座：本地重构与验收

本次修改针对规划、执行、审计和交付链路，不新增行业模板。
AI 仍只生成声明式计划；原始文件不覆盖，不能运行模型返回的代码。

## 实际发现并修复的问题

| 问题 | 修改 |
| --- | --- |
| 能力目录对所有操作展示同一套参数，且没有绑定执行器 | `operation_contracts.py` 统一操作名称、输入数量、必填/可选参数；注册器绑定现有校验器和执行适配器 |
| 直接构造 AgentPlan 可绕过参数和输入数量校验 | 预演和执行再次验证契约、步骤唯一性、上游引用、来源名称数量 |
| 部分报告允许 100 张表，但计划入口只接受 20 张 | 按操作契约使用对应上限 |
| 普通连接可能多对多扩行或空键相互匹配 | 连接前检查键、基数、预估行数；默认拒绝空键、多对多与 cross；显式批准仍受行数上限限制 |
| 每个操作的执行记录不一致 | 所有 AI 白名单步骤保留输入/输出行列数、内容指纹、参数哈希、耗时和契约版本；任务保存审计轨迹 |
| 一次业务异常只能增加专门函数 | 增加可组合的标准化、去重、异常分流、四则计算原语；业务模块继续作为适配器复用 |
| 报告验收失败后，任务里已经有成功记录和结果表 | 交付验收先完成，随后在锁内重新检查输入签名并提交任务 |
| 导出先覆盖旧文件，再发现校验失败 | 同目录临时文件生成、重开验收、领域检查、原子替换；失败保留旧文件 |
| 严格验收没有发现多余 Sheet，空验收可通过 | 检查实际 Sheet 集合；空预期表拒绝通过；读取 NA/N/A 等文本不当作缺失值 |
| 验收读取按预期行数截断，可能忽略多出的记录 | 读取完整数据区域，不靠截断掩盖行数不一致 |
| 血缘记录拿输入表名称按 ID 查找 | 名称/ID 均可解析，恢复输入血缘信息 |

## 执行链路

```text
自然语言 / 调用方提供结构化计划
    → 操作契约和参数校验
    → 上游引用与输入范围检查
    → 隔离副本上的白名单执行
    → 输出字段与资源上限检查
    → 逐步骤指纹与审计
    → 临时文件生成与重新打开验收
    → 领域检查（存在时）
    → 原子发布文件
    → 再核对任务/输入签名，提交结果与下载入口
```

`dry_run` 会在副本上实际执行，以发现类型和字段错误，但不提交到任务。
不能把预演成功理解为已生成正式交付文件。

## 可复用操作

- `normalize_fields`：指定列的 Unicode、首尾空格、大小写和精确名称映射；不猜别名，不把数值编码擅自变成文本。
- `deduplicate`：指定重复键；主输出保留记录，`rejected` 保留重复记录；缺失键或相同键不同内容默认停止。只有显式批准 `allow_conflicts` 才能按 `keep` 取舍冲突。
- `partition`：条件规则命中的记录进入 `rejected`，所有命中原因一起保留；其余进入 `primary`。
- `derive_columns`：按列/数值操作数做 add/subtract/multiply/divide，可逐步引用派生列；默认禁止覆盖字段和无效运算。显式 `errors=coerce` 才保留空值与 `review`，绝不自动填零。
- `validate`：原有质量报告保留兼容；`fail_on_error=true` 切换为质量门禁，通过时 primary 原样传递，阻断性失败时后续步骤不执行。

例如同一份计划可以组合：标准化 → 去重 → 分流取消/待支付 → 连接唯一商品主数据 → 派生贡献 → 分组汇总。
上游排除记录可以通过 `$step:rejected` 独立导出，不能只丢掉而不说明原因。
去重键应包含正确粒度（例如订单号+订单行号），不能把一单多商品误认为重复订单。

## 验收与边界

新增测试文件 `tests/test_structured_execution.py` 使用合成数据，覆盖完整处理链路、输入不变、契约一致、门禁、重复冲突、连接扩行、除零、NA 文本、额外 Sheet、额外行、交付失败回滚和服务器不提交成功状态。
已有客户订单、餐饮、库存、人员等回归测试继续执行。

没有宣称“任何 Excel 都能自动理解”。未知规则、缺失主数据、金额口径冲突仍需要澄清或人工核验。
此轮未调用真实 AI API，无法据此证明所有自然语言改写都能正确生成计划。
5 项外部电商 Golden Dataset 测试需要原测试文件，不得把跳过当作通过。

后续仍需要：

1. 将遗留手工按钮、recipe 子步骤与行业函数内部操作逐步收敛到同样的细粒度审计；本轮统一的是 AI 白名单步骤和主要交付入口，并非所有历史代码已拆完。
2. 明确每个指标的事实域、单位、时间归属及缺失策略；不靠执行规范代替业务正确性。
3. 增加更多去标识化 Golden Dataset，以及授权情况下的真实 AI 规划评测。
4. 压测大文件/并发、断电持久化恢复，并核查最终 Excel 视觉与图表语义；重开数据验收不等于完整 Office XML 或视觉验收。
