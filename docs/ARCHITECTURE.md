# 架构说明

表格快处 AI 采用“AI 理解、白名单编译、本地执行、交付验收”的分层设计。模型不直接获得任意代码执行权，也不直接修改用户原文件。

```text
浏览器单命令界面
        │
        ▼
自然语言路由 / 分析编译器
        │  只产生结构化意图与白名单参数
        ▼
参数归一化 + 本地安全校验
        │
        ├── 清洗 / 合并 / 匹配 / 对账
        ├── 财务 / 销售 / 库存 / 人力 / 经营诊断
        ├── 动态图表 / Excel 报告
        └── VBA / Power BI / 只读数据库工程交付
        │
        ▼
任务隔离存储 + 自动验收 + 人工核验边界
```

## 核心模块

| 模块 | 责任 |
|---|---|
| `server.py` | 本地 HTTP 服务、上传、任务和统一命令入口 |
| `nl_agent.py` | 模型协议、JSON 归一化、计划校验和白名单执行 |
| `analysis_compiler.py` | 需求意图、领域、字段语义、粒度、证据与图表计划 |
| `domain_packs.json` | 可配置行业身份词和标准业务概念 |
| `metric_semantics.py` | 金额、余额、比例、评分等聚合语义 |
| `core.py` / `analytics.py` | 确定性数据处理与分析 |
| `*_report.py` | 具有稳定业务口径的深度能力包 |
| `io_utils.py` | Excel/CSV 导入、样式、原生图表和安全导出 |
| `source_guard.py` | 输入隔离与历史输出污染保护 |
| `delivery_qa.py` | 导出后重开、指纹和数值合计验收 |
| `task_store.py` | 一单一目录、留存与恢复 |

## 通用分析编译器

编译器先根据需求、文件名、表名和字段名识别领域，再为每张表推断：

- `fact / dimension / summary / notes` 表角色；
- 日期、标识符、分类维度、数值指标和描述字段；
- 标准概念、聚合规则和置信度；
- 主数据粒度、可执行能力和缺失证据；
- 有业务意义的排名、结构、趋势和风险图表。

证据不足不会降级为猜测，而是进入报告的“证据缺口”和“人工核验”区域。

## 扩展原则

1. 新行业首先通过 `domain_packs.json` 扩展，不新增客户名字分支。
2. 新计算只有在口径稳定、可审计并能测试时才进入专用模块。
3. 模型输出始终经过本地 schema、类型、字段存在性和资源上限校验。
4. 任何跨表计算必须说明连接键、粒度和覆盖率，禁止不同粒度事实表直接相乘。
5. 所有导出都应通过 `verify_delivery` 或同等级重开验收。
