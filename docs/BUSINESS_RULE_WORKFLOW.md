# 通用分析：规则确认与复用

本轮新增横向业务规则层，让客户差异尽量通过规则解决，而不是复制客户专用报告。它没有替换所有行业引擎，也不是让 AI 执行任意代码。

## 使用入口

1. 重启本地服务，上传本次原始文件，输入分析需求，点击“通用规则分析”。普通命令走通用分析路径、发现歧义时，也会进入确认面板；行业路径保持原有行为。
2. 出现歧义时不再整单无输出：先自动生成“阶段分析与核验”Excel，页面提供下载入口。包含数据源确认、数据质量、语义契约、能支持的分析、主表明细、原始事实域记录索引及待确认事项；文件经过导出重读验证才发布。不同事实域不为阶段交付拼成稀疏宽表，其完整原始值在上传文件中保持不变。
3. 确认表角色、分析日期、有效/排除状态、去重键、指标聚合与单位。
4. 字段改名、名称/编码字典、同表加减或维度属性关联，在高级规则 JSON 中配置。再次变动表单会覆盖 JSON 编辑，务必最后核对。
5. 勾选确认后先预演；通过才颁发一次性执行凭证。生成报表后自动开始下载。
6. 可填写客户标识与配置名称保存。默认仍需再次核对；只有明确勾选自动复用、设置有效期、最大记录数和每表最大排除比例后，才生成可撤销的本地报表授权。
7. 下次点击“通用规则分析”，查询同一客户配置，选择“按已授权配置自动执行”。未授权、过期、撤销、超出主题范围，或状态/字段/单位/日期/业务键漂移时，系统明确说明阻断原因，不自动换规则。引擎更新也需重新核对。此配置分组不是多人系统的身份认证。

阶段交付不执行未批准的过滤、去重、关联、退款分摊、换汇或单位换算，也不把原始记录数称为有效订单数。它不是完整经营诊断；若某些指标不可计算，会明确保留证据缺口。阶段输出不会加入原始输入表列表。没有显式自动授权的保存规则仍需要本次确认；有效授权须在提交和执行前重新校验。发布前重新比较任务、结构和单元格内容指纹，输入变化则拒绝发布旧结果。

后台还分别检查“文件内容验收”和“需求主题验收”。文件生成不代表所有问题已回答，缺少利润、现金等主题证据时，界面保留下载并显示部分交付。详见 [自主交付边界](AUTONOMOUS_DELIVERY.md)。

源文件与上传表不被改写。使用规则时，原有 12 张报告表增加“规则处理审计”“规则排除明细”“原始记录留档”。留档是当前导入数据及记录位置，不是原 Excel 样式/公式/物理行号完整副本。

## 架构与责任

```text
本次显式源表 + 用户需求
          ↓
字段/事实域识别与口径缺口（推断，不是批准）
          ↓
人工确认规则 ← 客户配置 + 字段漂移检查
          ↓
版本化 JSON 白名单校验 + 任务/数据签名绑定
          ↓
确定性准备：映射、过滤、去重、隔离、派生、维度关联
          ↓
多事实编译：逐指标契约、独立分析、主题证据
          ↓
原始/排除/规则审计 + 图表 + Excel 导出重读验收
```

| 模块 | 责任 |
| --- | --- |
| `business_rules.py` | schema v1、确定性准备、原始/排除审计 |
| `business_workflow.py` | 规则建议、客户配置、字段漂移/同构歧义阻断 |
| `trusted_automation.py` | 显式本地报表授权、有效期/限额、撤销与执行前复核 |
| `task_acceptance.py` | 已声明需求主题、执行证据与文件验收分开判断 |
| `business_contracts.py` | 确认与推断口径分离、单位一致性、指标安全 |
| `analysis_compiler.py` | 独立事实域绑定；确认指标不再依赖名称猜聚合 |
| `adaptive_report.py` | 按确认上下文计算、排名、趋势及审计报表 |
| `server.py` | 审核/执行凭证、输入与发布边界 |

现有行业报告未大规模重写，也未自动获得新规则能力。需要通过通用入口使用横向规则层。

## 规则示例

以下是假设的合成字段，必须按实际表头修改；规则须覆盖全部选定源表。改名后引用新名称。

```json
{
  "schema_version": 1,
  "tables": [{
    "source_name": "本次文件.xlsx__订单",
    "role": "fact",
    "rename": {"付款额": "销售额"},
    "value_maps": {"门店": {"一店旧名": "一店"}},
    "date_field": "营业日期",
    "duplicate_key": ["订单号", "商品编码"],
    "statuses": {
      "订单状态": {"mode": "filter", "valid": ["已完成"], "invalid": ["已取消", "待支付"]}
    },
    "invalid_numeric": "block",
    "metrics": {
      "销售额": {"aggregation": "sum", "unit": "元"},
      "成本": {"aggregation": "sum", "unit": "元"}
    },
    "derived": [{"field": "毛利", "operator": "subtract", "left": "销售额", "right": "成本", "unit": "元"}]
  }],
  "joins": [],
  "requirements": ["profitability", "trend", "ranking"]
}
```

- 标准值字典只精确替换明确的分类/标识，不猜缺失值，不改写金额或日期。
- 聚合仅支持 `sum`、`mean`、`last`、`weighted_ratio`。比例需 `numerator`、`denominator`，单位 `%`；同样本完整且单位一致才计算。
- 日期选择是一种分析口径，不是跨期退款/结算分摊规则；无效日期仍阻断相关计算。
- 状态按精确值覆盖。新状态/缺失状态使过滤中止，不自动归为无效。`ignore` 必须明确表示不作为经营过滤条件，规则留档。
- 去重只删除同键且全部字段相同的记录。同键内容冲突、键缺失均中止；默认不删。
- `block` 保留异常记录并阻断相关指标；`exclude` 明确授权隔离整条记录，单列原因，不填零。隔离后事实域为空则中止。
- 同表派生仅同单位加减，不隐式换汇/换算；源声明与确认单位冲突仍阻断。
- `joins` 仅事实到唯一维度、100% 键覆盖的属性补充，禁止金额复制、扩行、两个事实域连接后求和。同时声明两张表的角色。

```json
{
  "left": "订单", "right": "商品资料",
  "left_key": "商品编码", "right_key": "SKU", "fields": ["商品类别"]
}
```

## 配置与安全边界

- 配置存在本机任务根目录 `.business_profiles`，按客户标识哈希分组，以随机 ID 保存 JSON。只存 schema、规则与标题，不存整张客户原始记录。
- 配置里的状态/分类字典也可能敏感，不要公开此目录。客户标识是本机配置分组，不是跨租户鉴权。当前为不可变快照，暂无配置删除 UI 或版本迁移。
- 不扫描目录寻找 Excel，不跨客户自动复用。表名变化仅在 schema 唯一匹配时提出复用；字段漂移、表数量变化、同构歧义拒绝复用。每次仍须重新确认，值域/币种/唯一性在预演时复核。
- 审核凭证绑定任务、表 ID、数据签名，15 分钟有效、成功确认后单次使用。数据变化或切换任务不能执行旧计划。
- 模型参数不能自行批准业务口径。HTTP 只能经人工确认颁发批准后的执行凭证；库调用方须自行保证授权。
- 含疑似 API Key 的规则、客户标识或配置名称不保存。保留原有公式注入防护与日志安全。

## 验收与尚未完成的能力

执行成功不等于所有问题已回答。服务器返回 `request_coverage`，报告保留“问题与证据”；有 partial/unavailable 主题时提示证据不足，不宣称完整诊断。

覆盖度是有限主题的本地检查，不是任意自然语言需求的完整语义证明。缺少成本、退款归属、目标或库存单位，不能通过确认按钮变成净利润、目标完成率或积压结论。

当前不支持任意跨事实分摊、自动同构合并政策、任意公式/阈值、自主业务决策或任意未知行业的自动正确诊断。复杂退款追溯仍使用已验证行业路径或后续明确规则扩展。

合成测试覆盖状态/重复/异常金额、双日期、自定义指标、字典、维度关联、币种、客户/schema 隔离、凭证、源数据不变、实际 HTTP 与 XLSX 重读。没有在本轮调用真实 DeepSeek，也没有做人工 Excel/WPS 视觉验收。
